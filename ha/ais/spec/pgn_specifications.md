# Спецификация NMEA 2000 PGN для AIS

## Обзор

Компонент `ais_targets` декодирует ограниченный набор AIS PGN напрямую из сырого потока шлюза YDNU-02, используя библиотеку `nmea2000` (форк проекта) только как декодер сообщений — без обращения к интеграции `nmea2000` в Home Assistant.

Список декодируемых PGN определён в `custom_components/ais_targets/const.py` (`ALL_AIS_PGNS`).

## Таблица поддерживаемых PGN

| PGN | Название | Категория | Частота | Обрабатывается |
|---|---|---|---|---|
| 129038 | AIS Class A Position Report | Позиция | Часто (несколько раз в минуту) | Да — позиционные поля |
| 129039 | AIS Class B Position Report | Позиция | Часто | Да — позиционные поля |
| 129040 | AIS Class B Extended Position Report | Позиция + частично статика | Часто | Да — позиционные + частично статические поля |
| 129041 | AIS Aid to Navigation (AtoN) Report | Служебный | Редко | Декодируется, но не участвует в отображении целей |
| 129793 | AIS UTC and Date Report | Служебный | Редко | Декодируется, но не участвует в отображении целей |
| 129794 | AIS Class A Static and Voyage Related Data | Статика/рейс | Редко (раз в неск. минут) | Да — статические поля |
| 129809 | AIS Class B Static Data Report, Part A (имя) | Статика | Редко | Да — статические поля (имя) |
| 129810 | AIS Class B Static Data Report, Part B (тип/позывной/размеры) | Статика | Редко | Да — статические поля |

### Источник данных

Согласно проведённому анализу живого трафика шины (см. отчёт `ha/ais/ais_pgn_discovery.md`), источник AIS-сообщений на шине — **Alltek AIS 208253**, source address **31 (0x1F)**. Реально наблюдались PGN 129038, 129039, 129793, 129809, 129040, 129041, 129794 от нескольких активных целей (примеры MMSI: 232053931, 238052410, 2620002, 249759000, 518159228, 325137100).

## Идентификация судна: поле MMSI

Во всех AIS-сообщениях MMSI (Maritime Mobile Service Identity) закодирован в поле библиотеки `nmea2000` с идентификатором `userId` (`FIELD_MMSI` в `const.py`). Это поле является ключевым для группировки всех входящих сообщений (позиционных и статических) в единую запись цели по MMSI.

```python
FIELD_MMSI = "userId"
```

### Валидация координат

Полученные широта/долгота принимаются только если они попадают в допустимый диапазон (`-90 ≤ lat ≤ 90`, `-180 ≤ lon ≤ 180`) — это защищает от отображения цели с явно некорректными («нулевыми»/битыми) координатами.

## Маппинг полей статических PGN (129794 / 129809 / 129810 / частично 129040)

| Поле nmea2000 | Атрибут цели | Обработка |
|---|---|---|
| `name` | `vessel_name` | очистка от паддинга (см. ниже) |
| `callsign` | `callsign` | очистка от паддинга |
| `typeOfShip` | `ship_type` | LOOKUP → строка |
| `length` | `length` | метры, округление до 0.1 |
| `beam` | `beam` | метры, округление до 0.1 |
| `destination` | `destination` | очистка от паддинга |
| `etaDate` + `etaTime` | `eta` | объединение в единую строку (см. ниже) |

### Очистка строковых полей (`_clean_str`)

AIS-строки (имя, позывной, порт назначения) в стандарте часто дополняются символами-заполнителями. Функция `_clean_str` в `ais_bus.py`:
1. Удаляет NUL-байты (`\x00`).
2. Удаляет символы `@` (стандартный AIS-паддинг).
3. Обрезает пробелы по краям (`strip()`).
4. Возвращает `None`, если после очистки строка пуста (чтобы не показывать в интерфейсе пустую строку вместо «—»).

### Формирование ETA (`_format_eta`)

Библиотека возвращает `etaDate` и `etaTime` как отдельные значения (дата/счётчик дней и время/секунды). Так как надёжно собрать из них единый абсолютный timestamp без риска ошибки нельзя, они просто объединяются в человекочитаемую строку `"<date> <time>"` (или только одна из частей, если вторая отсутствует).

## Формулы конвертации единиц

| Величина | Формула | Константа |
|---|---|---|
| Скорость (SOG): м/с → узлы | `sog_kn = sog_ms * 1.9438444924406046` | `_MS_TO_KNOTS` |
| Курс/пеленг: радианы → градусы | `deg = degrees(rad) % 360` | `math.degrees` |
| Скорость поворота: рад/с → град/мин | `deg_per_min = degrees(rad_per_s) * 60` | — |

## Разбор CAN ID (`parse_can_id`)

Каждый кадр на шине идентифицируется 29-битным CAN ID, из которого извлекаются `pgn` и `source address` — идентично логике `ydnu02/pgn_decoder.py`:

```python
def parse_can_id(can_id_hex: str) -> tuple[int, int, int]:
    can_id = int(can_id_hex, 16)
    pgn_raw = (can_id >> 8) & 0x3FFFF
    src = can_id & 0xFF
    pdu_format = (pgn_raw >> 8) & 0xFF
    if pdu_format < 240:
        pgn = pgn_raw & 0x3FF00
    else:
        pgn = pgn_raw
    return can_id, pgn, src
```

Этот разбор выполняется **до** передачи кадра в декодер `nmea2000`, чтобы отбрасывать все не-AIS кадры максимально дёшево (без затрат на полное декодирование FastPacket).

## Обработка PGN 129040 (Class B Extended Position Report)

Данный PGN уникален тем, что несёт **и** позиционные, **и** часть статических полей одновременно (в частности, имя/тип судна для Class B целей, транслирующих расширенный отчёт). Поэтому в `ais_bus.py._ingest()` для этого PGN вызываются обе функции обработки — `_apply_position()` и `_apply_static()`:

```python
if pgn in AIS_POSITION_PGNS:
    self._apply_position(target, fields)
if pgn in AIS_STATIC_PGNS or pgn == 129040:
    self._apply_static(target, fields)
```

## Защита от «зависших» целей без позиции

Статическое сообщение само по себе не должно продлевать жизнь цели, у которой никогда не было позиции (`has_position == False`) — иначе цель без координат никогда не попадёт под таймаут устаревания, но и никогда не будет показана на карте. Поэтому `last_seen` обновляется статическим сообщением только если позиция уже присутствует:

```python
if target.has_position and target.last_seen is None:
    target.last_seen = dt_util.utcnow()
```
